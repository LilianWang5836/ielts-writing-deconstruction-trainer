# 方案：新架构下 coach 专业感提升 + Planner 阶段启发式问答

> 评估日期：2026-08-16 | 状态：仅方案（未改代码）| 基线：`v0.5.1-restructured`（会议秘书架构）
> 目标：让 coach 在新架构下显得更专业、更智慧；**重点在 Planner 阶段引入启发式问答**。

---

## 1. 诊断：现状为什么"显得不专业、不智慧"

| # | 现状 | 后果 |
|---|------|------|
| 1 | **Planner（Step 2.5）是完全静默的黑盒**：Step2 完成 → CTA"进入第三步" → 前端自动调 `/api/planner/generate`（Step2Brainstorm.tsx:436）→ 骨架静默生成 → 用户点"进入第三步"。学生**全程看不见"为什么这样分段/哪点详写/让步放哪"**。 | coach 没有任何一处展示"结构/策略判断力"——这是最有"教练专业感"的地方，却完全缺席。 |
| 2 | **Step3 教练被明确禁止谈结构**（server.ts:8303/8461）：`Do NOT propose paragraph modes / pointBlock splits... the skeleton is already frozen`。 | 教练=槽位播音员（问 firstEmpty + 推确认按钮），零结构话语权。 |
| 3 | **Step2 教练被硬门禁 + 按钮流约束**（CHECKLIST FIRST / CHECKLIST BEFORE STANCE / 每侧详略 采纳/拒绝 + 立场 采纳/拒绝）。 | 教练只能走流程，无法展示"权衡取舍"的判断。 |
| 4 | **判断透镜（P2）只做内部审计**：`step3Assessment.verdict/reason` 不进对话文本（"server uses it for audit + hints — never echo it"）。 | 教练明明有"判断"，却不说给学生听，智慧感被浪费。 |
| 5 | Step3 开讲文案只有"我们开始构建这个主体段。"（server.ts:4260），无 plan 呈现。 | 学生不知道"我们为什么写这一段"。 |

**结论**：秘书架构把"结构/判断"全部收归确定性机制，稳定了，但把 coach 的**专业表现空间**清空了。要恢复"专业感"，不是回到 v0.3 让 LLM 管结构，而是**在"结构还没冻结"的地方（Planner 阶段）重新给 coach 一个基于材料的、启发式的结构对话窗口**——既守住"骨架冻结后只读"的底线，又把"结构决策的教学"还给教练。

---

## 2. 设计原则（新架构下成立的前提）

1. **结构冻结前可对话，冻结后只读**：启发式结构问答只发生在 **Planner 骨架冻结之前**（Step2.5 阶段）；骨架一旦冻结（进入 Step3），任何环节不得改结构——这是消灭死锁的底线，绝不触碰。
2. **专业感 = 在结构决策处给出"有依据的判断" + 让学生做选择**：教练引用学生自己的材料说明"为什么这样写更有利"，然后给出选项让学生决策——不是替学生写，是教学生"为什么"。
3. **启发式问答 = 轻量、跟材料走、带理由**：每处 ≤1–3 轮、问题必须有材料依据、有默认建议可"跳过"。**不得** reintroduce 硬门禁、长流程或强制确认（那是上一个问题的反面教训）。
4. **复用现有机制，不建平行架构**：提案通道（`side_settle`/`stance`，proposal.ts）、Planner 输入（planner-prompts.ts）、判断透镜（lens.ts）都是现成抓手；只扩展，不推翻。
5. **尊重"反 LLM 代劳"**：教练引导**结构决策**，学生内容（论点/论证）仍由学生产出；教练不写句子、不加事实。

---

## 3. 核心方案：Planner 阶段改为"段落结构对话"（Essay Architecture Dialogue）

三件事按"前置 → 后置 → 逐段"组合：

```
Step2 完成
   │
   ├─ 3.1 前置结构对齐（pre-planner）← 启发式问答核心，骨架未冻结
   │     教练给候选策略 + 理由 + 1 个启发式问题 → 学生选（layout_strategy 提案，采纳/拒绝）
   │     ↓ 学生选择作为"软参数"传给 Planner
   ├─ Planner 生成冻结骨架（现有 /api/planner/generate 不动核心）
   │
   ├─ 3.2 后置方案确认（post-planner recap）← 教练大白话汇报 + 请确认
   │     ↓ 确认后进入 Step3
   └─ 3.3 逐段透明（Step3 kickoff recap）← 每段开讲 1–2 句说清"论证什么、为何在这"
```

### 3.1 前置结构对齐（pre-planner，启发式问答的核心）

**时机**：Step2 材料池+立场已锁定、Planner 运行之前（即现在的 CTA"进入第三步"出现处，插一个轻量微阶段）。

**教练输出（一屏/一轮）**：
1. **一句话策略判断**（基于学生材料，非模板）：例："你的支持方材料更具体（通勤/午休两条都有场景），反对面只有一条监督。这种偏科材料，通常更有利的写法是：**主体段1 全力展开优势，主体段2 做让步**——既保住立场，又显得思考全面。"
2. **1 个启发式问题**（只问最有教学价值、且材料真的两可的决策点，不问废话）：
   - 段数 2 vs 3：当两个点都"可独立展开"且都详写时 → "这两个点都够扎实，是分两段各写一段，还是并成一段主次分明？"
   - 让步段位置（前/后）：当立场需要让步时 → "让步放在最后一段收尾，还是放前面先承认再反驳？前者更常见，后者更有冲击力。"
   - 展开角度（例证 / 机制因果 / 影响）：当某点材料有多种展开法时 → "这个点你是想用具体场景讲（举例），还是把因果机制讲透？"
   - （详略角色已有 `side_settle` 提案，不重复问。）
3. **默认建议 + 可跳过**：末尾给一个"照推荐开始"的默认路径，学生可直接"采纳"，不强制回答。

**机制落地**：
- 新增提案 `kind: 'layout_strategy'`（proposal.ts，参照 `stance` 提案实现，`decisionTypeForProposalKind` 加一行），按钮复用「采纳/拒绝/自定义」。
- 学生选择写入 `plannerPayload.layoutPreference = { bodyCountPref?, concessionOrder?, expansionPref? }`（**软参数**）。

**Planner 侧**：
- `buildPlannerInput` / `buildPlannerPrompt` 增加一个"学生结构偏好（软参考）"输入块；prompt 加一条规则：*若学生已确认结构偏好，优先采纳；但若与材料硬约束冲突（如跨侧不混段、详写点必须 major），以材料约束为准，并在 rationale 注明*。
- **关键**：偏好是 preference 不是 hard lock —— Planner 仍保留最终判断权，防止学生乱选破坏骨架质量；骨架仍由 Planner 冻结，Step3 结构零改动。

### 3.2 后置方案确认（post-planner recap）

**时机**：Planner 生成骨架成功、进入 Step3 之前。

**教练输出**（大白话，禁内部字段名）：
- "好，结构定了。这一篇我们写 **两段**：第一段 **展开你的优势点**（在职人员通勤/午休碎片化学习，材料最具体）；第二段 **承认局限**（低龄学生需要线下监督），收尾回到立场。先写哪段随你，我们按这个蓝图逐段打磨。"
- 引用 `step2_5.rationale` + `bodyPlans[].role/label/subClaim` 转成自然语言（可做一个 `renderPlanRecap(skeleton)` 的纯函数，从 skeleton 投影，确定性产出，不由 LLM 自由发挥）。

**机制落地**：纯文本层（Step3 开讲前插入一段 coach recap），可带一个「照此开始」确认；**不新增结构字段**。这块补回 v0.3 曾有、v0.5.1 丢失的"向学生呈现篇章布局"的价值。

### 3.3 逐段透明（Step3 kickoff recap）

**时机**：进入 Step3 每个 body 的第一轮（kickoff）。

**教练输出**（1–2 句）：基于当前 body 的 `skeleton.block.role/label/subClaim`：
- "这一段我们论证**线上学习的优势**（你的通勤/午休碎片化材料）。先补这句分论点：为什么这种灵活特别适合在职者？"
- 替换现在干巴巴的"我们开始构建这个主体段。"

**机制落地**：改 kickoff 的 ContextSummary，把当前 body 的"角色/主题/一句话使命"传给 coach（已有 skeleton，只加 2–3 个字段的投影），prompt 加一条"开讲须先用一句话点明本段论证目标"的规则。纯文本层，结构零改动。

## 4. Step2/Step3 内 coach 专业感的补充手段（配合 3，增强整体"智慧感"）

| 手段 | 做法 | 落地点 |
|------|------|--------|
| **判断进对话** | 把 `step3Assessment.verdict/reason`（现在只做内部审计）转成教练 1 句专业点评："这个回答把机制讲透了，但还没落到'对谁、造成什么'，这环（结果/影响）补上才完整。" | server.ts Step3 分支：把 verdict→自然语言映射，`text` 允许带一句"专业点评"（不放模板）。 |
| **偏薄追问带教学** | 学生回答偏薄时，追问解释"为什么需要这个要素"（论证逻辑教学），而非只重复"请说具体一点" | Step3 prompt JUDGMENT LENS 段 + lens.reason 复用 |
| **允许专家判断** | 学生问"哪个更好写/怎么选"时，教练直接给推荐+理由（现有 INTENT CLASSIFICATION 已有此意图，可强化），而非永远中立 | Step2/3 prompt |
| **结构诊断反馈** | 段落收尾时给 1 句"这段逻辑链缺了 X 环"的结构诊断（对应 Stage 5 已定义的 Structure Diagnosis 精神），不重写 | Step3 单 body 完成时 |

> 这些都是"文本层 + prompt 规则"改动，不碰骨架冻结/落槽机制，风险低。

## 5. 落地路径（分期，可独立验收）

| 阶段 | 内容 | 改动范围 | 风险 | 验证 |
|------|------|---------|------|------|
| **P1（先做，低风险）** | 3.2 后置方案确认 + 3.3 逐段透明 | 纯文本：Step3 prompt 的 ContextSummary/kickoff 文案 + `renderPlanRecap(skeleton)` 纯函数 | 极低（不碰状态/提案/骨架） | 三题型 E2E：进 Step3 前能看到"方案汇报"、每段开讲有点题；tsc+replay 全绿 |
| **P2（核心诉求）** | 3.1 前置结构对话（启发式问答） | 新增 `layout_strategy` 提案（proposal.ts）+ `layoutPreference` 软参数 + planner prompt 输入扩展 + Step2.5 微阶段状态机 | 中（新增一个提案类型 + planner 输入，需守住"偏好非硬约束"） | 交互式学生脚本：结构对话 ≤3 轮、学生可采纳/自定义/跳过；Planner 在偏好与材料冲突时仍出合法骨架 |
| **P3（配合）** | §4 教练专业点评 | server.ts 把 `step3Assessment.reason` 映射进对话 + prompt 规则 | 低 | 记录会话检查：点评出现、不套模板、不 reintroduce 机械感 |

> 建议顺序：**P1 立即做**（成本最低、立刻缓解"黑盒"感）→ **P2 是本次核心**（满足"Planner 阶段启发式问答"）→ P3 随 P2 一起或后置。

## 6. 风险与边界

1. **流程感反噬**（上一轮"生硬推流程"的教训）：
   - 控制：每阶段 ≤1–3 轮；问题必须有材料依据；有默认建议，学生可"采纳/跳过"；**不加硬门禁**（门禁只管状态，不管对话自然度）。
   - 验收红线：任何新加的问答都不得成为"必须点完才能走"的强制步骤。
2. **LLM 代劳**（秘书架构初衷）：
   - 教练只引导**结构决策**、给理由和选择；论点/论证内容仍由学生产出。结构偏好只进 planner 软参数，不变成教练写句子。
3. **骨架冻结边界**：
   - 结构对话/偏好必须发生在 **Planner 冻结之前**；Step3 内只做"透明呈现"（3.3），**绝不**允许结构修改（保留 secretary 只读底线）。
4. **Planner 稳定性**：
   - `layoutPreference` 是软参数；与材料硬约束冲突时以材料为准（Planner 仍兜底，rationale 注明）。避免学生乱选破坏骨架质量。
5. **字段泄漏**：
   - 所有方案汇报用自然中文（禁 `layoutPattern/bodyCount/pointBlock` 等），复用现有 "NO INTERNAL JARGON" 规则。
