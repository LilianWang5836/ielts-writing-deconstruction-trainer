## T1：P1 侧别标签服务端加固（小改，先做）

**背景（审查发现的问题）**：按侧计数门禁依赖 LLM 给每个维度打`（侧：A/B/G）`标签。`preserveStep1ProbeTags`（`src/server/step1/dimension-probe.ts:76`）对**状态戳**（已探测/可展开等）有改写恢复机制，但对**侧别标签**没有——LLM 某轮改写维度时丢掉侧标签，该维度立即变"未归属"不计数，门禁可能中途从通过变不通过。

**注意一个连带坑**：`stripStep1StatusTags` 计算 core 时是否剥离侧标签，直接决定丢标签后 core 是否还能匹配上 prior 记录。先读 `dimension-probe.ts` 弄清现状再动手。

**要求**：
1. 让侧别标签享有与状态戳同级的恢复待遇：core 匹配计算应剥离侧标签（侧标签不算核心文案）；当 prior 同 core 维度带侧标签而新一轮丢失时，恢复 prior 的侧标签。
2. LLM **显式改变**侧标签（A→B）时尊重新值，只恢复"丢失"的情形。
3. 新出现（无 prior）的维度不加杜撰侧标签——那是 prompt 层职责。
4. 在 `scripts/verify-p1-per-side.mts` 或新脚本中补用例：改写丢侧标签 → 恢复；改写换侧 → 尊重新值；core 匹配不受侧标签有无影响。

**验收**：`npm run lint` 零错误 + 新用例通过 + 一阶段 4 个 verify 脚本不回归。

## T2：P5 折中方案实施——每侧批量一次确认

**已定方案**（需求方已拍板）：不做逐点确认，做**每侧批量一次确认**，且为守住"净轮次不增"红线，**点位确认并入现有 `side_settle` 提案**（该提案本来就每侧出现一次，净轮次为零增量）。

**规格**：
1. `planner-payload.ts`：`points[]` 增加确认标记（如 `confirmed?: boolean`），实时抽取的新点默认未确认。
2. `side_settle` 提案升级：呈现内容从"仅详略建议"扩展为"**该侧点位清单 + 详略建议**"，学生一次采纳 = 该侧点位全部确认入池 + 详略锁定；拒绝/自定义路径保持现状语义（点位保持未确认，详略未锁定，学生可继续补充修改后再触发）。
3. 触发时机维持 `sideReadyForSettle`（`src/server/step2/proposal.ts:103-122`）不变。
4. planner 输入只消费已确认点（`confirmed === true`）；`slot_add` 通道确认的点直接视为已确认。未确认点不得进入 planner。
5. 材料池 UI（`Step2Brainstorm.tsx:755-897`）：点位卡片加 待确认/已确认 徽标。
6. 提案互斥：同一轮只允许一个 pendingProposal，检查与 `slot_add`/`slot_merge`/`stance` 的交互。
7. 兼容性：存量会话（points 无 confirmed 字段）按"未确认"处理但不要卡死流程——若 side_settle 已采纳过，将该侧存量点标记为已确认（迁移逻辑放在读取侧，不改历史数据）。

**注意**：`docs/prompt-ds-requirements-alignment-2026-08-16.md` §7.4 的方案 A 五步计划可作参考，但确认粒度以本任务的"每侧批量"为准，不是逐点。

**验收**：
- Step2 全流程：点位实时入池（待确认）→ 该侧就绪后提案卡片含点清单+详略 → 采纳后该侧点全部转已确认 → planner 输入只含已确认点；
- 拒绝提案后点位保持待确认、可继续积累并再次触发；
- `npm run lint` 零错误；`scripts/replay-proposal-channel.mjs`、`replay-proposal-phase1.mjs` 等现有 Step2 回放通过（若断言因提案内容变化需更新，更新断言并在 §8 记录原因）。

## T3：LLM 端到端走查（最后做，需要 API key 与 dev server）

纯函数验证已覆盖确定性逻辑，但以下两点必须过真实 LLM 链路。用 `npm run dev` 起服务，参考 `scripts/replay-full-journey.mjs`、`scripts/interactive-student.mjs` 的用法（见脚本头部注释）：

1. **Step1 侧标签稳定性（双边题）**：跑一道 Discuss Both Views 题的 Step1 全程，检查：(a) 维度侧标签在多轮改写后仍保留（T1 加固生效）；(b) "A 侧 3 点 B 侧 0 点"被拦截且提示指向 B 侧；(c) 不再出现"反复要角度"的死循环。
2. **Step3 结构要约全流程**：(a) 表达"我想换第二个论点"→ 教练给要约；(b) **穿插正常作答后再打"对" → 不得触发重规划**（验证 §7.6 修复在真实链路生效）；(c) 重新表达结构异议 → 确认 → 前端重跑 planner 成功重建 Step3；(d) 武装要约后拒绝 → 无副作用继续。
3. **P5 冒烟**：Step2 走完一侧，确认提案卡片正确呈现点清单+详略、采纳/拒绝路径正常。

结果（通过/失败 + 现象）写进交付总结；失败的项先修再交付。
