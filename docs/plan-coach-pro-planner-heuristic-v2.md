## 3. 核心方案（按新优先级）

### P0 — Step3 落槽管线修复（功能层，先做，改动集中在 server.ts + secretary.ts）

**P0-1 质量门控接回落槽（对应 F3，Kimi ②）**
- `landMinuteToSlot` 增加一个前置门：先 `evaluateMinute`（或复用 dup 预检 + 透镜），按 verdict 分流：
  - `duplicate` / `off_target` / `off_topic` → **不 landed**（保持 `recorded` + `rejectReason`），教练一句引导回到当前槽/换新角度；
  - `thin` → **landed 但带 `偏薄待补` 标记**（draft 上板 + 标记），教练允许 **1 次**针对性追问；`activeSlotIndex` 不推进（防"薄内容占位后跳槽"）；
  - `ok` → 正常 landed，等确认。
- 守 anti-loop：任何槽至多 1 次 thin 追问；第二次仍薄则照常 landed（不无限拒绝）。
- 意义：**确认时机 = 内容达到可写质量后才落槽确认**，文本（"还偏薄"）与看板（无 draft/带标记 draft）一致。

**P0-2 元评论识别（对应 F2，"重复追问失忆"）**
- 分类前增加元评论匹配（确定性正则，先保守）：`我(前面|刚才|之前|前面)说(过|了)?|刚(才|刚)说(过|了)?|已经(说|写|确认)(过|了)|这个(说|答)(过|了)?|重复了|再说一遍` 等。
- 命中 → **不落槽**：`appendMinute(recorded)` 存档但 `slotKey` 留空；服务器从 `minutes`/`landingLog` 找出该槽已落内容回显一句（"对，这一步你已经说了：…"），并让 `activeSlotIndex` 推进/给下一问。
- 意义：学生指出"已说过"时，教练**接得住**（不再失忆式重复问、不再把元评论当内容）。

**P0-3 批量落槽（对应 F4，也是轮次削减主来源）**
- 单条学生消息可覆盖多个槽（如"分论点是…，原因是…"）：解析为若干 clause → 逐个对**连续空槽**做语义匹配落槽 → 一次性 `landed`（多条 minutes 各自带 slotKey）→ 学生**一次确认**全部。
- 复用/重接 v0.3 遗留的 `pendingDrafts` 批确认语义（server.ts:3253-3272），迁到秘书路径。
- 边界：仅在"同一轮原话确实覆盖 ≥2 个连续空槽"时批量；否则单槽（防为了省轮次而强塞）。
- 意义：Step3 主要轮次成本（逐槽"答→确认"两拍）显著下降，为 P1 腾预算。

**P0-4 审计打通（评估闭环基础）**
- `landingLog`（P1 已有）每条追加 `verdict`（透镜）与 `source`（isAff/isRej/元评论/批量/单槽），供 §5 量化统计与回归断言。

### P1 — Planner 前置启发式问答（表现层核心，骨架冻结前；沿用 v1 3.1）

时机：Step2 完成、Planner 运行前；新增 `layout_strategy` 提案（复用 `side_settle/stance` 通道），教练给 1 句材料依据的判断 + 1 个启发式问题（段数 2/3、让步位置、展开角度），学生选择作为**软参数**（`layoutPreference`）传 Planner；冲突以材料为准。

> 轮次账：P1 新增 ~1–3 轮，由 P0-3 批量落槽在 Step3 省回的轮次对冲 → **净轮次不增**（见 §4）。

### P2 — 结构透明 + 判断进对话（沿用 v1 3.2/3.3/§4）

- 3.2 后置方案确认（进 Step3 前大白话汇报骨架）
- 3.3 逐段透明（每 body 开讲点题）
- 判断进对话：P0-1 之后，verdict 已**落地为行为**，P2 只在 `thin/off_target` 时补 1 句"为什么"（把 `lens.reason` 转自然语言），不重复矛盾提示。

## 4. 轮次预算表（净不增）

| 位置 | 现状轮次 | v2 变化 | 净效果 |
|------|---------|---------|--------|
| Step3 逐槽"答→确认" | 每槽 2 拍（v0.3 遗留/现状） | P0-3 批量落槽 → 覆盖多槽时 1 拍（一答+一批确认） | **-30~50%（多槽轮）** |
| Step3 重复追问 | 学生重复/元评论被当内容，教练再问 | P0-2 识别"已说过" → 指回/推进，不重问 | **-2~3 轮/次** |
| Step3 薄回答 | thin 已 landed，教练与看板打架 | P0-1 门控 → 至多 1 次追问后放行 | 0（受 anti-loop 约束） |
| Planner 前置启发式问答 | 0（静默） | P1 +1~3 轮 | **+1~3** |
| Planner 后置确认 + 逐段透明 | 0 | P2 +0~1 轮 | **+0~1** |
| **净** | | | **≈0 或为负** |

红线：`总轮次（回归集内）不得高于现状基线`；若 P1 净增超过 Step3 省回量，先压 P1 问题数，不先砍 Step3 稳定性。

## 5. 评估闭环（新增，防退化）

**回归集**（基于现有 `replay-*.mjs` 与记录会话，扩充场景）：
1. 正常三题型旅程（agree/discuss/ps）
2. **元评论**：学生说"这个刚才说过了/我前面已经说了" → 不落槽、指回、推进（P0-2）
3. **薄回答**：thin → 至多 1 次追问后放行，看板一致（P0-1）
4. **多句一答**：一条覆盖 2 槽 → 一次批量确认（P0-3）
5. **Planner 启发式问答**：≤3 轮、可采纳/自定义/跳过、偏好与材料冲突时 Planner 仍合法（P1）
6. 全部通过 `replayLanding`（P1 审计重放）一致性校验。

**量化指标（每次改动前后对比，写入评估文档）**：
- 总轮次 / 会话（对照 §4 基线）
- 卡死次数（`detectStall` 报警数）
- 撤销率（`rejected` 落槽 / 总落槽）
- thin 追问率（`thin` 触发 1 次追问占比，防无限循环）
- 落槽误判数（元评论/非内容被 landed 的次数 —— 应=0）
- 看板-文本矛盾次数（verdict 非 ok 但看板显示 draft —— 应=0）

**机械流程红线**（对应 v0.2→v0.3 教训）：
- 任何新增对话不得成为强制步骤（可跳过、有默认建议）
- 不新增硬门禁（门禁只管状态）
- 回归集内 `text` 不应出现模板重复句（抽样检查重复率上限）
